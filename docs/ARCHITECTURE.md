# Архитектура Afterlife Overdrive

## Обзор

```
apps/client  ──►  packages/sim ──► packages/procgen ──► packages/content ──► packages/shared
   (DOM, Pixi,       (детерм.          (генерация            (данные: спрайты,      (RNG, мат.,
    звук, сеть)       симуляция)        данжей по seed)       предметы, враги)       протокол)
apps/server  ──►  packages/sim (тот же код в Durable Object)
```

| Пакет              | Что внутри                                                                                                                                                    | Правила                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `packages/shared`  | seeded RNG (sfc32), детерминированная тригонометрия (`dsin/dcos/datan2`), бинарный писатель/читатель, `PlayerInput`, версии протокола/сохранений, `TICK_RATE` | Без DOM, без `Math.random`/`Date` (ESLint)                       |
| `packages/content` | Весь контент как типизированные данные: палитра, пиксельные спрайты, paper-doll, тайлсеты, (M1+) оружие, артефакты, аффиксы, враги, биомы, шаблоны комнат     | Новый предмет/враг/биом = новый файл данных                      |
| `packages/procgen` | Типы карты (`DungeonFloor`, `Tile`), генераторы биомов, граф комнат, валидатор                                                                                | Детерминирован: один seed → один данж                            |
| `packages/sim`     | ECS на typed arrays (SoA), фиксированный шаг 30 Гц, коллизии с тайлами, игроки, (M1+) бой, ИИ, лут                                                            | Чистая функция `step(world, inputs)`; работает в браузере и в DO |
| `apps/client`      | Vite + Preact (меню/HUD в DOM) + PixiJS v8 (только рендер), ввод, звук, i18n, PWA                                                                             | Код меню и игры в разных чанках                                  |
| `apps/server`      | Cloudflare Worker: статика (Workers Static Assets), `/api/*`, Durable Object на комнату, D1                                                                   | Сервер ничему не верит: zod + rate limit                         |

Пакеты экспортируют **исходники TypeScript** (`"exports": "./src/index.ts"`): Vite, Vitest и
wrangler (esbuild) компилируют их напрямую, отдельной сборки пакетов нет.

## Детерминизм

- Симуляция и генерация используют только `+ - * /`, `Math.sqrt/floor/round/abs/imul` — они
  побитно одинаковы во всех движках. `Math.sin/cos/atan2/pow/random`, `Date`, `performance`,
  `setTimeout` в `packages/*` **запрещены линтером** (см. `eslint.config.js`).
- RNG: sfc32 с сидированием splitmix32, `deriveSeed(seed, 'label', n)` для независимых потоков
  (например, отдельный поток лута на каждого игрока).
- Ввод квантуется (`mx/my` int8, угол прицела — байт), поэтому соло, предсказание клиента и
  сервер видят одинаковые числа.
- Тест `step.test.ts` проверяет, что два прогона с одинаковым вводом совпадают побитно.

## Симуляция (`packages/sim`)

- `Entities` — struct-of-arrays на `Float64Array/Int32Array/...`, ёмкость 1024, free-list,
  поле `gen` для обнаружения «протухших» ссылок. Ноль аллокаций в тике.
- `step(world, inputs)` — один тик (1/30 с). Порядок систем: служебные таймеры → игроки →
  (M1) ИИ → снаряды → урон → смерть → подборы → комнаты/двери.
- События тика (`EventBuffer`, тоже SoA) клиент превращает в звук, частицы, тряску; сервер (M3)
  отправляет их в снапшотах.
- Коллизии с картой: AABB по осям (`moveBox`), флаги тайлов `BlockWalk`/`BlockShot`;
  закрытые двери — динамические флаги `map.dyn`. Линия видимости — DDA по тайлам.
- (M1) Сущность-сущность: spatial hash (ячейка 32 px), пересобирается каждый тик.

## Генерация этажа (`packages/procgen`)

`generateFloor({ seed, biome, depth, floors })` — детерминирована, с внутренними повторами
(до 40 попыток с производными seed'ами), пока этаж не пройдёт `validateFloor`.

1. **Раскладка** (`layout-bsp.ts`): BSP делит карту до нужного числа листьев (8–12), в каждом —
   прямоугольная комната с отступом ≥3 тайла. Кандидаты в рёбра — пары соседних листьев;
   случайное остовное дерево (Kruskal) + до 2 петель. Коридор — A* по «якорям» кисти 2×2,
   которым запрещено касаться комнат и их стен; двери — 2 тайла в стене комнаты.
2. **Граф и роли** (`roles.ts`): реальный граф строится заливкой компонент коридоров. Старт —
   «лист» с максимальным эксцентриситетом, последняя комната — самая дальняя (мини-босс с
   лестницей или босс), перед боссом — мини-босс, сокровищница — лист вне главного пути
   (заперта), ключ — дальняя боевая комната, магазин — по возможности лист.
3. **Наполнение** (`populate.ts`): ASCII-шаблон интерьера по типу комнаты (откатывается, если
   разрывает комнату), шипы, спавны волн из пула биома (с учётом глубины), сундук, витрины
   магазина, лестница, декор (факелы на верхней стене, паутина, кости, щебень).
4. **Проверка** (`validate.ts`): достижимость всех комнат (сокровищница — с ключом), нет
   запечатанных карманов, спавны и интерактивы на достижимом полу, двери проходимы. Тест —
   1000 seed'ов.

`pnpm floor-map <seed> [depth] out.png` рисует этаж в PNG (цвета по типам комнат).

## Игровая симуляция (`packages/sim`) — системы

Порядок в `step()`: таймеры → spatial hash тел → игроки (ввод, рывок, атака, артефакты, зелье,
взаимодействие, движение) → поле потока (каждые 6 тиков) → союзники → враги (ИИ) → снаряды →
области → статусы → подбор → ловушки → замки → комнаты/волны/двери.

- **Оружие** — архетипы атаки из данных: `melee_arc` (дуга + отражение снарядов), `thrust`
  (выпад), `projectile` (с `melee`-подстраховкой для посоха). Урон × уровень предмета ×
  (1 + урон%) × крит.
- **Артефакты** — список эффектов: `projectile` (прицельный/радиальный), `area` (сразу или с
  задержкой), `dash`, `buff`, `heal`, `shield`, `summon`.
- **ИИ врагов** — состояния `Spawning → Move ⇄ Windup → Act → Recover`. Движение: `chase`,
  `keepDistance` (стрейф), `wander`, `erratic`, `still`; без прямой видимости — по полю потока
  (BFS от игроков). Атаки: `melee`, `projectile` (очереди, веер, спираль, кольцо), `charge`,
  `hop`, `summon`, `area`, `blink`. Фазы босса меняют список атак.
- **Комнаты**: вход на ≥1 тайл внутрь → двери закрываются (динамические флаги), волны по
  очереди; зачистка открывает двери и выдаёт награду (ключ, лестница, портал, зелья).
- **Лут личный**: каждый живой игрок получает свои дропы (владелец в `Drop.owner`), seed
  предмета выводится из seed забега → проверяемое происхождение.
- **Команды** (`equip`, `drop`) применяются хостом между тиками — тот же путь будет у сервера.

Тесты sim: детерминизм, боты проходят этажи и убивают босса, soak со случайным вводом,
perf-guard тика (сейчас ~0.25 мс при всех активных комнатах).

## Поток забега (клиент)

`GameScreen`: первый запуск → выбор оружия и артефакта → профиль. Забег: 3 этажа крипты;
лестница → «Глубже / Уйти с добычей»; портал после босса → победа; смерть → итоги (найденное
потеряно, снаряжение начала забега остаётся). Профиль M1 — `localStorage` (`state/profile.ts`).

## Рендер (`apps/client/src/game`)

**Главное условие производительности:** канвас рендерится в низком внутреннем разрешении, а
браузер растягивает его целым коэффициентом с `image-rendering: pixelated`.

- `computeViewport()` выбирает целый масштаб `scale` так, чтобы по высоте было видно ≈15 тайлов
  (240 логических px). Например, iPhone 13 (DPR 3): 1170 px → ×5 → 234 px; Pixel 7: ×4.
  Пиксельный буфер ~ 500×240 вместо 2532×1170 — в 25 раз меньше пикселей.
- Один атлас (`Atlas`) собирается при старте на canvas из палитровых пиксельных карт
  (+ белые силуэты для вспышки попадания). Спрайт можно заменить PNG без правок кода:
  `apps/client/src/assets/sprite-overrides/<id>.png`.
- Paper-doll: `composeCharacter()` из `packages/content` склеивает слои (ноги, торс, броня,
  голова, глаза, причёска, шлем) с палитровыми свопами и автоматической обводкой; результат —
  маленький отдельный лист `Sheet` на персонажа.
- Карта «запекается» в чанки 16×16 тайлов (256×256 px canvas → текстура): пол, стены с лицевой
  гранью, тени, ободки, декор. Невидимые чанки скрываются (`cull`).
- Слои: пол → декали → актёры (сортировка по y) → свечение (additive) → эффекты → верх.
- `WorldView` сопоставляет сущности sim → спрайты (пул по слоту сущности), анимирует (бег,
  телеграф, прыжок, смерть, оружие в руке с замахом) и превращает события тика в эффекты,
  звуки, тряску и hit-stop. `Fx` — пулы частиц, цифр урона и одноразовых анимаций.
- Звук — `apps/client/src/audio/sfx.ts`: слои осцилляторов в духе sfxr рендерятся в
  AudioBuffer при первом проигрывании.
- Камера: сглаженное следование, ограничение краями карты, тряска; `roundPixels` для чёткости.
- Цикл: собственный `requestAnimationFrame`, фиксированный шаг 30 Гц с аккумулятором
  (не более 5 шагов за кадр), интерполяция позиций между тиками. Пауза при скрытой вкладке.

## UI (Preact, DOM-оверлей)

- Меню и HUD — DOM поверх канваса, шрифт Pixelify Sans (кириллица) из `@fontsource`.
- Сенсорное управление пишет напрямую в `InputManager` (без ре-рендеров на каждый move).
- Все строки через `t('key')` (`apps/client/src/i18n/ru.ts`).
- `?debug=1` — оверлей FPS/кадр/тик/сущности/seed/разрешение.
- Любая необработанная ошибка → экран с отчётом (версия, стек, состояние, устройство, лог) и
  кнопкой «Скопировать отчёт». Экран на чистом DOM — работает, даже если упал Preact.

## PWA

Собственный маленький плагин `apps/client/build/pwa.ts` (без зависимостей): генерирует иконки
(пиксель-арт → PNG при сборке), `manifest.webmanifest` (fullscreen, landscape) и `sw.js`, который
прекэширует всю сборку (соло работает офлайн). Навигация — network-first (новый деплой
подхватывается), ассеты — cache-first. Новая версия ждёт и предлагает «Обновить» в меню.

## Сервер (`apps/server`)

- Один Worker: статика клиента через Workers Static Assets (`run_worker_first: ["/api/*"]` —
  запросы статики **не тратят** лимит запросов Worker'а), `/api/*`, Durable Objects, D1.
- `RoomDO` — Durable Object на комнату, SQLite-backed (единственный вариант на Free),
  WebSocket Hibernation API.
- D1: миграции в `apps/server/migrations/*.sql`, применяются в CI перед деплоем.
- Два окружения: `production` (ветка main) и `preview` (все остальные ветки, отдельный Worker и
  своя база). Preview URLs Cloudflare не работают для Worker'ов с Durable Objects — поэтому так.

## Сеть (M3)

```
клиент (телефон)                                   Worker               RoomDO (код комнаты)
  POST /api/rooms {char}  ───────────────────────►  auth, rate limit ─► admit(): место + seat
  POST /api/rooms/CODE/join {char} ───────────────►  auth ──────────────► admit()
  WS /api/rooms/CODE/ws?seat=… ───────────────────►  (без auth) ────────► acceptWebSocket
       ◄─ JSON: welcome, lobby, floor, inv, look, vote, result, runEnd
       ◄─ binary: снапшот 15 Гц          ─► binary: изменения ввода (≤10/с), JSON: start, vote…
```

- **`RoomCore`** (`apps/server/src/room-core.ts`) — вся логика комнаты без зависимостей от
  Cloudflare (тестируется в Node): лобби (места, лидер, кик, открытость), запуск забега,
  30 Гц `step()` из `@ao/sim`, очереди ввода, снапшоты, голосование на лестнице, итоги.
  `RoomDO` (`room.ts`) — тонкая обвязка: Hibernation API, storage, таймер, D1-каталог.
- **Ввод** (`@ao/shared/net.ts`, `@ao/sim/net/inputs.ts`): клиент нумерует тики, шлёт только
  изменения; `InputQueue` на сервере применяет по одному номеру за тик (буфер джиттера 2 тика,
  адаптивный), `ack` — последний смоделированный номер.
- **Снапшоты** (`@ao/sim/net/snapshot.ts`): `FieldCapture` квантует поля один раз за тик,
  `SnapshotEncoder` на клиента шлёт изменения против «веры» о клиенте: сущности (создание с
  видом/поколением, маска изменённых полей, удаление), мир (ключи, двери `dyn`, тайлы замков,
  состояния комнат, проданные витрины), игроки (прицел, рывок, смерть, поднятие, версия облика),
  «я» (точное состояние движения + `ack` для реконсиляции, HUD) и события тиков. Личный лут
  других игроков клиенту не отправляется.
- **Клиент** (`apps/client/src/net`): `Party` — HTTP + WebSocket, переподключение с
  повтором 0.3–4 с в пределах 45 с (`online`/`visibilitychange` — сразу), ping каждые 30 с в
  лобби и 2 с в забеге. `NetRun` — зеркальный `World` (`createMirrorWorld`), декодер,
  `Predictor` (предсказание и повтор неподтверждённого ввода), часы сервера и очередь событий.
  `GameHost` в сетевом режиме рисует зеркало тем же `WorldView`.
- **Переподключение:** место держится 45 с; сервер повторно шлёт `floor` + полный снапшот,
  сбрасывает очередь ввода; неподтверждённый `result` отправляется снова.
- По сети не передаётся карта — только seed: этаж генерируется на клиенте и совпадает побитно.

## Сохранения и аккаунт (M2)

- **Модель** (`packages/sim/src/save.ts`, zod): `AccountSave { v: 2, rev, updatedAt,
characters[], realms: { standard, hardcore }, settings }`. Герой: внешность, хардкор,
  происхождение, уровень/опыт/характеристики, снаряжение, зелья, эликсир, статистика, сюжет.
  Реалм: склад (≤120), золото, материалы, счётчик крафта, рынок, контракты.
- **Миграции**: `migrateSave()` превращает профиль M1 (`ao.profile.v1`) в героя «Странник».
- **Клиент** (`apps/client/src/state/account.ts`): IndexedDB (`db.ts`) — источник истины на
  устройстве; `mutate()` пишет локально и через 2.5 с отправляет в облако.
- **Синхронизация**: `GET /api/save` → если сервер новее и локально нет изменений — берём
  серверное; иначе `PUT /api/save {baseRev, save}`. Сервер принимает запись только при
  `baseRev == rev` (оптимистичная блокировка) → 409 с актуальной версией при конфликте.
- **Аккаунт**: `POST /api/account` → токен устройства (на сервере SHA-256). Код
  восстановления: `POST /api/account/recovery` (новый код, хранится хеш),
  `POST /api/account/recover {code}` → новый токен для того же аккаунта.
- **Забег**: `POST /api/runs` выдаёт seed (пишется в `runs`); офлайн — локальный seed.
- **Rate limit** (D1, фиксированное окно): создание аккаунта и восстановление — 10/час на IP,
  новый код — 5/час, забеги — 60/час, сохранение — не чаще раза в 2 с.
- Тесты API — `apps/server/test/*.test.ts` на `node:sqlite` (тот же SQL, что в D1).

## Хаб и экономика (M2)

- Хаб — ASCII-карта `HUB_MAP` + станции `HUB_STATIONS` (`packages/content/src/data/hub.ts`):
  объект и/или NPC (paper-doll), сюжетный флаг для появления. Сцена — тот же `GameHost` в
  режиме хаба; взаимодействие → событие `Ev.Talk` → панель станции (DOM).
- Все операции хаба — чистые функции `packages/sim/src/account.ts` (экипировка, кузница,
  алхимик, рынок, статуя, контракты, применение итогов забега).
- Итоги забега: опыт всегда; смерть — потеря найденного за забег (хардкор — смерть героя);
  успех — надетое остаётся, сумка → склад, золото → реалм; прогресс контрактов.

## Бюджет бесплатного тарифа Cloudflare

Лимиты Workers Free (проверены в октябре 2026 через поиск по документации Cloudflare;
сами страницы developers.cloudflare.com из облачной сессии недоступны):

| Ресурс                           | Лимит в сутки                                                      |
| -------------------------------- | ------------------------------------------------------------------ |
| Запросы Worker                   | 100 000 (статика через Static Assets — бесплатно и не считается)   |
| CPU Worker                       | 10 мс на вызов                                                     |
| Durable Objects: запросы         | 100 000 (HTTP, RPC, WebSocket-сообщения, алармы)                   |
| DO: входящие WebSocket-сообщения | считаются как 1 запрос за 20 сообщений; исходящие — бесплатно      |
| DO: длительность                 | 13 000 ГБ·с (объект 128 МБ → ≈ 101 600 с ≈ 28 ч активного времени) |
| DO: хранилище SQLite             | 5 млн строк чтения, 100 000 строк записи, 5 ГБ                     |
| D1                               | 5 млн строк чтения, 100 000 строк записи, 5 ГБ                     |

Расчёт на один кооп-забег (4 игрока, 15 минут):

| Статья            | Расчёт                                                                              | Итого                                 |
| ----------------- | ----------------------------------------------------------------------------------- | ------------------------------------- |
| Подключения WS    | 4 (+ переподключения)                                                               | ~6 запросов                           |
| Ввод              | только изменения, ≤10 пакетов/с; клавиатура ~1/с, джойстик ~4–8/с: 4 × 6 × 900 / 20 | ~1 100 запросов (худший случай 1 800) |
| Служебные         | ping 2 с в забеге (если платформа его считает): 4 × 450 / 20                        | ~90 запросов                          |
| Длительность DO   | 900 с × 0.125 ГБ                                                                    | 112.5 ГБ·с                            |
| D1 в конце забега | ~6 записей на игрока                                                                | 24 записи                             |

- **Узкое место — длительность DO:** 13 000 / 112.5 ≈ **115 кооп-забегов в сутки**
  (≈ 460 игроко-забегов). По запросам DO: 100 000 / 1 900 ≈ 50 в худшем случае и ≈ 85 в
  среднем (джойстик). Для хобби-проекта достаточно; соло не зависит от DO вообще.
- Измерено в тесте/`wrangler dev`: снапшот в тихой комнате ~110 байт, в бою 2 игрока ~1 КБ;
  ~1.6 КБ/с исходящего трафика на игрока (исходящие сообщения DO бесплатны).
- **Соло** не трогает DO вообще: ~5 API-запросов на забег (seed, сохранение) → десятки тысяч
  забегов в сутки.
- Как держим бюджет: Hibernation API в лобби (простаивающая комната не платит за
  длительность), тик-цикл запускается только на время забега, пустая комната закрывается через
  N секунд, никакого поллинга (список комнат — по запросу при открытии экрана), автоответ на
  `ping` без пробуждения объекта, исходящие снапшоты бесплатны.

## CI/CD

`.github/workflows/ci.yml` на каждый push:

1. **check**: ESLint → Prettier → `tsc` во всех пакетах → Vitest → сборка → бюджет бандла
   (`bundle-budget.json`, `scripts/check-bundle-size.mjs`) → `wrangler deploy --dry-run`.
2. **e2e**: Playwright в эмуляции Pixel 7 и iPhone 13 (landscape): меню → игра → джойстик →
   движение, рывок, экран ошибки, без ошибок в консоли. Скриншоты — в артефактах.
3. **deploy**: `scripts/cf-deploy.mjs`. Без секретов — пропуск с понятным сообщением.
   С секретами: поддомен workers.dev → база D1 (создаётся при необходимости) → миграции →
   деплой → проверка `/api/health`. `main` → production, остальные ветки → preview; ссылка
   превью — комментарием в PR.

Бюджет бандла (gzip): начальный JS ≤ 30 КБ, CSS ≤ 10 КБ, чанк игры ≤ 220 КБ, весь JS ≤ 420 КБ.
