# Журнал решений

Формат: решение — почему. Новые записи добавляются в конец.

## M0

1. **Версии стека:** TypeScript 5.9, Vite 7, Vitest 3, ESLint 10 + typescript-eslint 8,
   Preact 10, Zod 4, PixiJS 8, wrangler 4. На npm уже есть TS 7 (нативный порт), Vite 8,
   Vitest 5, Preact 11, но typescript-eslint поддерживает TS < 6.1, а мажорные версии с новыми
   API — лишний риск. Обновляться отдельными PR.
2. **Свой SoA-ECS вместо bitecs.** Нужен полный контроль над детерминизмом, сериализацией в
   снапшоты и нулём аллокаций; bitecs 0.4 сменил API. Свой вариант — ~150 строк.
3. **Детерминированная математика.** `Math.sin/cos/atan2/pow` не обязаны совпадать в V8 (Chrome,
   workerd) и JSC (Safari). Свои `dsin/dcos/datan2` на полиномах (+−×÷ — точны по IEEE 754),
   RNG sfc32 на 32-битных операциях. Линтер запрещает опасные API в `packages/*`.
4. **Тик 30 Гц** для sim/сервера; снапшоты 15 Гц (M3). Достаточно для отзывчивого боя и
   укладывается в бюджет Durable Objects.
5. **Низкое внутреннее разрешение + CSS-апскейл целым коэффициентом** (`image-rendering:
pixelated`) вместо рендера в полном разрешении: в 9–25 раз меньше пикселей на DPR 2–3.
6. **Пакеты экспортируют TS-исходники**, без шага сборки — проще и быстрее; все потребители
   (Vite, Vitest, esbuild в wrangler) понимают TS.
7. **Свой PWA-плагин** (~100 строк) вместо vite-plugin-pwa/workbox: меньше зависимостей,
   предсказуемый service worker, иконки генерируются из пиксель-арта при сборке (нет бинарников).
8. **Шрифт Tiny5** (@fontsource) для всего UI: пиксельный, с нормальной кириллицей (у Pixelify
   Sans стилизованные «в», «ы» читаются как «е», «bl» — проверено рендером). Pixelify Sans 700
   оставлен только для латинского логотипа. `font-synthesis: none` — без размазанного «жирного».
9. **CI только на push** (без `pull_request`), т.к. статусы коммита видны в PR, а у приватного
   репозитория 2000 бесплатных минут Actions в месяц — двойные прогоны их съедают.
10. **Превью — отдельный Worker `afterlife-overdrive-preview` со своей D1**, общий для всех
    веток (последний push побеждает). Cloudflare Preview URLs не работают для Worker'ов с
    Durable Objects.
11. **Создание D1 и поддомена через REST API Cloudflare** в `scripts/cf-deploy.mjs` (не через
    парсинг вывода wrangler) — надёжнее; `database_id` подставляется в сгенерированный
    `wrangler.deploy.jsonc`, в репозитории только плейсхолдер.
12. **Персонаж 16×24, слои без контура + автоматическая обводка** композиции: проще рисовать
    слои, контур всегда цельный. Броня — общие формы + палитра материала (кожа, железо, …);
    сапоги — палитровый своп ног (без отдельного арта).
13. **Playwright 1.56.1 закреплён**, потому что в облачных сессиях Claude предустановлен
    Chromium именно этой версии (`/opt/pw-browsers`), а `playwright install` там запрещён.
    В CI браузер ставится `--only-shell`.
14. **Рывок у всех**: 1 заряд, 0.2 с, перезарядка 0.9 с, неуязвимость 0.3 с. Аффиксы могут
    добавлять заряды. **Слоты брони**: шлем, нагрудник, сапоги (как в предложении).
15. **Первый биом — крипта** (BSP-комнаты и коридоры): естественно ложится на механику
    «двери закрываются до зачистки». Лес — второй биом в M4 (глава 1 = лес + крипта).
16. **Мерж PR — «Create a merge commit»**: этапы делаются цепочкой веток; squash заставил бы
    вручную разрешать конфликты в следующем PR.
17. **Hit-stop только на клиенте** (локальная пауза рендера/соло-сима), а не в sim: в
    мультиплеере заморозка сервера остановила бы всех игроков.

## M1

18. _*BSP + граф по соседним листьям + A*-коридоры._* Комната в каждом листе BSP, рёбра — только
    между соседними листьями (коридор гарантированно проложим), случайное остовное дерево +
    ≤2 петли. Коридоры могут пересекаться, поэтому **роли комнат назначаются по реальному графу**
    (заливка компонент коридоров), а не по задуманному — это убрало целый класс софтлоков.
19. **Сокровищница — всегда «лист» вне главного пути**, все её двери запираются; ключ падает
    после зачистки самой дальней боевой комнаты, достижимой без ключа.
20. **Враги = движение + список атак** (телеграф → действие → восстановление). Новые враги —
    только данные; босс — фазы со своими списками атак. Так же легко сделать элиту и аффиксы
    врагов позже.
21. **Лут личный и детерминированный:** seed предмета = `deriveSeed(runSeed, 'drop', игрок,
номер)`. Сервер сможет перегенерировать и проверить любой предмет (аукцион). Магазин —
    `deriveSeed(runSeed, 'shop', этаж, слот)`.
22. **Подбор предметов — в сумку (12 мест), пустой слот экипируется сразу.** Смена снаряжения —
    через инвентарь командами, которые применяет sim между тиками (в мультиплеере их будет
    принимать сервер).
23. **zod в игровом чанке**: контент парсится при старте (значения по умолчанию + проверка).
    +~15 КБ gzip к игре, зато сломанный контент не доходит до игрока. Меню zod не грузит.
24. **Профиль M1 — localStorage** (`ao.profile.v1`): снаряжение, склад, золото, статистика.
    В M2 мигрируется в IndexedDB + облако. Смерть = возврат к снаряжению начала забега.
25. **Сложность**: HP врагов ×(1 + 0.3·этаж)×(1 + 0.6·(игроки−1)), урон ×(1 + 0.15·этаж)×
    (1 + 0.1·(игроки−1)). Баланс — отдельная задача M5.
26. **Анти-туннелирование**: `moveBox` дробит перемещения на шаги ≤6 px (был баг: рывок
    нетопыря проносил его сквозь стену за пределы комнаты).

## M2

27. **Сохранение — один JSON-документ аккаунта** (`AccountSave` v2: герои + два «реалма»
    standard/hardcore) с ревизией. Сервер хранит его целиком в строке D1 (≤256 КБ) — 1 запись
    на сохранение, минимум строк в лимитах D1. Конфликт: если поменялись обе стороны, побеждает
    более свежий `updatedAt`.
28. **Local-first**: игра всегда работает из IndexedDB; облако догоняет в фоне (дебаунс 2.5 с,
    экспоненциальный повтор). Сервер недоступен → статус «нет связи», игра не блокируется.
29. **Токен устройства и код восстановления хранятся на сервере только как SHA-256.** Код —
    12 символов base32 (60 бит); перебор закрыт rate limit'ом по IP (10/час).
30. **Rate limit в D1** (фиксированное окно), без платных сервисов. Сохранения — не чаще раза в
    2 с на аккаунт.
31. **Сервер проверяет схему и границы** (уровень ≤60, золото ≤1e9, склад ≤200, …). Полная
    проверка происхождения предметов (перегенерация из seed) — вместе с аукционом.
32. **Экономика и прокачка — чистые функции в `@ao/sim`** (`account.ts`, `economy.ts`):
    одни и те же правила на клиенте и (позже) на сервере. Рынок NPC идёт через операции
    `marketBuy/marketSell` — в это место встанет аукцион.
33. **Товар дня рынка детерминирован** (`seed реалма + номер дня`), цены продажи падают при
    продаже однотипных вещей (насыщение, полураспад — сутки).
34. **Бонусы происхождения** приведены к существующим статам (вместо «сопротивления огню»):
    грузовик +4% бега, пожар +8% силы артефактов, ток −6% перезарядки, сон +0.5 HP/с,
    крыша +4% крита.
35. **Хаб — ходибельная сцена на том же движке** (ASCII-карта + станции как пропсы), а не меню:
    дёшево (переиспользует рендер и ввод) и атмосферно. Станции требуют сюжетных флагов —
    в M4 NPC будут «переезжать» после спасения.
36. **Предпросмотр (vite preview) без прокси API**: e2e идёт без Worker'а, клиент уходит в
    офлайн-режим; тесты игнорируют сетевые ошибки `/api`.
